# Game-Ready Asset Standard

版本：0.1 · 草案，待批准

## 交付单位与预算

一个资产使用稳定 `asset_id`、类别和版本追踪，并保存原始来源、Blender 工作文件、贴图、导出文件、检查报告与人工签核记录。变更后报告必须匹配当前文件版本；影响外观、拓扑、骨架、动画或导出结果的变更使对应签核失效。

预算按类别和用途制定，记录三角面、顶点、材质槽、贴图尺寸/内存、LOD、屏幕占比、同时出现数量。平台与镜头尚未确定，因此不规定统一面数上限；没有预算时报告“预算未配置”，不得宣称性能合格。4K 及以上贴图先给警告，是否允许由用途和预算决定。

## 技术交付要求

| 领域 | 要求 | 判定边界 |
|---|---|---|
| 几何 | 统计实际导出网格三角面/顶点；检查零面积面、松散元素、重叠候选、法线和拓扑异常 | 开放面、双面叶片、分离发片等可能有意；非流形不一律阻断 |
| UV | 使用图像贴图的表面具有所需 UV；记录 UV 名称与数量 | 无贴图、平铺或程序化方案按已批准材质规则判断；UV 重叠可能用于镜像/堆叠 |
| 材质 | 无必需贴图缺失；材质槽有效；材质数量符合类别预算 | Blender 节点效果不能默认等价于 Unity；须在目标管线重建或验证 |
| 贴图 | 记录路径、用途、尺寸、颜色空间及 alpha；外部依赖可随交付解析 | Base Color 与数据贴图按用途配置；法线方向与通道打包按 Unity 实际材质验证 |
| 尺寸/变换 | Blender 建议采用公制、1 单位=1 米；尺寸符合类别配置 | Unity 中验证最终实际尺寸；不能对绑定角色直接套用变换 |
| 轴心/方向 | 资产声明落地、握持、旋转等轴心用途；约定 Unity Y 向上、Z 向前 | 导出轴转换由导出配置完成，在 Unity 实测；不得手工重复旋转抵消 |
| 组织 | 对象、Mesh、材质、贴图具有稳定命名；导出集合明确 | 不包含无关隐藏对象、测试灯光/相机等；共享依赖需显式记录 |
| 碰撞 | 按用途声明无碰撞/交互/阻挡/战斗碰撞，并在 Unity 验证 | Collider 通常在 Unity 配置，Blender 仅提供可选代理网格；存在代理不等于已生效 |
| LOD | 声明必需/可选/不适用；需要时验证切换 | 不要求所有小道具都有 LOD；角色与文化资产减面须人工审查 |
| 角色/动画 | 骨架、蒙皮、动作列表、Root Motion 策略、挂点与必要表情能力有明确约定 | 检查缺失权重、异常变形、穿插与武器互动；动作质量由人工判断 |
| 导出 | 可重现配置、明确集合/对象、格式、版本、轴、单位、动画选项和依赖 | FBX 可作候选；最终格式和 Unity 导入配置待项目确认 |

## Unity Validation Scene

固定并记录 Unity 版本、渲染管线、导入配置、参考镜头和照明。每个资产检查：尺寸与方向、落地/握持轴心、材质与贴图、法线/透明/阴影、碰撞、LOD、角色变形与动作，以及实际游戏视角下的轮廓和视觉层级。用米制参考物和已批准 Golden 进行对照。

性能结论须来自目标平台或已约定的测试设备与场景负载；单个模型面数合规不能保证游戏性能。

## 状态与放行

- **🔴 NOT READY**：存在阻断问题，例如必需贴图丢失、导出失败、必需骨架/动作缺失、Unity 导入错误，或人工明确拒绝。记录原因和修复方向。
- **🟡 REVIEW**：无已知阻断，但有警告、预算/配置待定、未完成 Unity 验证或任何必需人工审查未签核。
- **🟢 READY**：当前版本技术检查无未解决重大问题，必要 Unity 验证完成，全部必需人工审查通过。经人工批准豁免的警告必须记录理由与适用范围。

判定顺序：阻断 → NOT READY；否则未签核/未验证/未处理警告 → REVIEW；全部满足 → READY。技术检查通过只记录 `technical_pass`，不能直接标记 READY。

Pipeline 决策另记 `Approved / Needs Review / Reject`：由人工做出。READY 是批准的必要条件；没有人工 Approved 不进入正式发布资产目录。
