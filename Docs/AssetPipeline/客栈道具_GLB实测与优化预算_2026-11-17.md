# 客栈道具 GLB 实测与优化预算 · 2026-11-17

当前为源资产评估。原始 GLB 未改动；以下预算用于首轮 Blender 出样，Unity 尚未验收。

- **实物清点：52 件，共 13,982,700 三角面、约 907.60 MiB。** Quest 5、Hackathon 39、InnInterior/v002 7、InnInterior/v003 1。扫描范围内另有 37 个 PNG、1 个 ZIP、0 个 SPZ。Q01 ZIP 内还有一份不同哈希的 MODEL.glb 和原始贴图，属于同一药箱的打包交付，单列排除。Q05 v001/v002 只有参考图；v003 的纸团为唯一落盘的 Q05 GLB。
- **复用关系：** 52 个 GLB 没有字节完全相同的副本。Hackathon 的床榻、饭碗、竹筷、床边药渍杯、小陶药瓶是客栈的复用候选，沿用这五份源文件。床边药渍杯在游戏里已有灰盒与线索归属；普通矮茶盏可多处复用，但应和药渍杯保持独立，饭碗也保留其残食或药粉用途。Q02 镖号剑鞘和 W03 剑是不同资产；先按剧情归属核对剑、鞘与柜台挂点。
- **两版花几：** v002「花几与彩色瓶花」447,868 面、27.86 MiB，留作备选；v003「瘦高花几与五彩瓶花」414,120 面、25.71 MiB，指定用于二楼客房过道。两者各自计数，各是一个网格 primitive；不能假定花、瓶、几已有独立可编辑部件。
- **统计口径：** 读取 GLB 默认场景节点的 primitive，以三角索引（或非索引顶点）数除以三。材质槽列为场景实际引用的材质数及 primitive 数。贴图体积读取内嵌 PNG 字节数；其余 GLB 字节包含几何、容器等。RGBA8 是按像素数估算的未压缩占用，完整 mip 链约乘 4/3；不是 Unity Profiler 数值。
- **贴图发现：** 每件均含 3 张 2048² PNG，但每件材质只引用 image 0（底色）和 image 2（金属度/粗糙度）；image 1 未被材质引用。可先剔除未引用图，核对渲染前后，再决定其余图的分辨率。两张图均按 RGBA8 时为 32 MiB/件（无 mip），实际应以 Unity 目标平台压缩格式和加载行为实测。源 GLB 的贴图占比 28–76%；W02 达 76%，先整理贴图更有利于减文件体积；Q04 只有 28%，应先重建纸张网格。

下表预算为单件 LOD0 及带内嵌贴图 GLB 的试做目标。压缩后的 Unity 包体另测；以同镜头可读性作为放行条件。P0 是当前客栈首批，P1 是客栈第二批，P2 按场景需求取用。

| 档 | 用途 | LOD0 三角面 | GLB 目标 MiB | 优化方式 |
|---|---|---:|---:|---|
| A | 药箱近景 | 4–5k | 1–4 | 箱口、扣件和开合边保轮廓；近景底色试 2K，检查取药热点和开合状态 |
| B | 镖号剑鞘、账本及特色兵器 | 3–10k | 1–4 | 保鞘边、镖号、账本封面与页边；关键底色保 2K 直到近景对照通过；细纹进贴图 |
| C | 纸、药包、饭碗、药渍杯和药瓶 | 0.5–4k | 0.5–2.5 | 手令用低面薄折纸和原字纹；药包保折角，杯碗保口沿和残留；文字或药渍糊时单独保 2K 底色 |
| D | 花几、脸盆架等中型置景 | 4–10k | 0.8–3 | 细腿、瓶口与花枝先保剪影；五彩花头先看过道实际画面再简化；底色先试 1K |

| J | 单人床榻 | 4–8k | 1–3 | 床架重建、薄席和枕被保轮廓，折纹进烘焙；保床脚与床尾通行 |

Blender 首批建议以 v003 花几、Q04 手令、床边药渍杯为三件打样：分别验证复杂轮廓、近景文字、微小残留。原始模型留在原目录，优化版放到独立目录并镜像源路径。记录源模型包围盒、根变换和轴心，导出后回读比对；保持原 UV 的方案先试，重建或拓扑破坏 UV 时才重展并从原模转移/烘焙底色与必要细节。

Unity 后续在 InnPlayable_v2 对照原镜头。v003 放于二楼 Y=4.35 m 的中央走廊侧边，避开房门、墙角转身区、楼梯落脚点；文档标称走廊宽 3.5 m，具体位置从场景实测。无互动装饰视需要用简化阻挡代理；有剧情归属的道具只替换 Visual，保留原碰撞/交互根和锚点。走查门洞、第三人称贴墙转身、床边、桌底和药箱，记录替换前后同设备同路线的 CPU/GPU 帧时及实际贴图占用。沿用 shader 对话已落地的约定：客栈置景和柜台兵器用 URP Lit，使用暖晨光与偏冷环境补光；仅随身兵器有需要时试角色两段明暗，角色本轮暂缓。导入时核对底色 sRGB、金属度/粗糙度的线性通道与 Unity Smoothness 映射。

逐件实测如下，可在项目根目录运行 `python3 Tools/Aholo/audit_inn_props.py` 重现表格。

## 首轮交付实测

Blender MCP 批量处理 52 件，优化版见 `ArtSource/Props/AholoOptimized`，共 237,122 三角面、117.12 MiB。批处理脚本为 `Tools/Aholo/optimize_inn_props.py`。本轮保留源 UV，以 Blender Decimate 输出初版。Q04 实际剩 11,800 面，后续近景精修可重建折纸。床边药渍杯为 2,212 面，瘦高花几为 9,512 面。

Unity `InnPlayable_v2` 的 Play 模式实测加载 17 件，均使用 URP Lit。Unity 首轮材质接入原底色和统一光滑度，GLB 保留原材质数据。二楼花几落点为 (-1.42, 4.35, 10.85)，落点旁射线命中走廊木板 Y=4.35，花几碰撞代理盒内的实测重叠结果只有自身。过道实拍见 `Docs/Art/Previews/Inn_Corridor_OptimizedProps.png`。本轮 Console 编译检查无错误。单次编辑器读数约 343 FPS，路线帧时、剧情全流程和调查文字可读性仍待完整走查。通用兵器、植被、户外道具及旧版花几已出优化 GLB，作为可选资产。
