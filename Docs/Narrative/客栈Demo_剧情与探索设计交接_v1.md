# 客栈 Demo：剧情、探索与分支设计交接 v1

日期：2026-11-03。用途：供负责 Unity 开发的对话参考；本文件是设计规格，不要求立即实现全部内容，不包含代码。

## 1. 范围与设计原则

Unity 6000.0.60f1；已有两层客栈灰盒、第三人称移动、镜头和调查交互。目标时长约 15—25 分钟。

固定开场：女主二楼醒来，下楼见大堂血迹、同行者昏迷、老板在柜台后擦剑。
固定通关条件：同行者已醒、女主持有老板的剑、两人走出客栈。

调查可以不完整，顺序自由。信息改变可说的话、人物是否主动交代、取剑方式和离店约定。不得要求收齐真相才能离开，不使用善恶值，不将调查充分等同于道德正确。

制作范围：两层客栈、三名在场人物、一个离场客人的痕迹；不新增战斗、追逐、配药小游戏或可见掮客。同行者醒来后可坐起、交谈并缓慢随行。

## 2. 已确定设定与本版落地建议

已确定：女主暗中调查师傅当年遭正道围攻而死的阴谋；短期接受原照顾者委托，安全送受伤同行者回家。同行者身负异能、携带被觊觎的宝物、金发醒目，不愿回家，但与女主个人约定暂时回去并协助调查。该约定不授权家中派来的人接管她。同行者担心女主见到手令后将自己交给掮客。

已选择方向：同行者主动设法取得手令；老板提供改貌药；客人另下昏睡毒；老板有护送活人的旧事，剑与旧事有关。

下文关于药笺、藏匿点、具体证据、结局数量和触发条件均为本版落地建议，可调整。尚未确定人名、宝物能力、家庭阴谋及师门案细节，不在 Demo 内擅自揭晓。手令真实不等于家中所有人恶意。

## 3. 作者层面的完整真相

### 前史

原照顾者推荐这间客栈，并告诉二人：老板曾走镖，懂得遮掩行迹，可向他购买换容药。老板认识原照顾者，但不是无条件可信的盟友。

老板过去与掮客合作护送活人。他曾按契约将一名不愿回家的人交付，后来听闻其被关押、下落不明。他无法确定全部后果，却不能否认自己的责任。后来他放走另一名被送者，导致掮客赔钱并得罪雇主。老板退隐开店；掮客认为老板拿自己的生计赎罪，老板则不愿继续替他办事。两人旧识使掮客仍敢进店接头，老板过去也未彻底切断往来。

### 昨夜时间线

1. 女主与同行者入住。女主休息后，同行者仍在楼下活动。无需额外设定女主也中毒。
2. 晚饭期间，掮客从金发等特征认出同行者，在她的饮食中下缓慢起效的昏睡毒，准备深夜带走她。
3. 同行者发现掮客持有家中某人签发的接人手令，内容要求找到后就地看管、等待接应。她担心女主将此理解为可以转交护送。
4. 她没有逃走，也没有取消与女主的约定。她想先拿到手令，保留与家中谈判、追查来路的筹码。她还不敢先将决定交给女主。
5. 她以原照顾者的名字试探老板，购买并知情服用改貌药。老板从细节猜到身份，知道她要躲避客人，但起初不知道偷手令的全部计划。老板没有隐瞒重伤用药经验的桥段。
6. 改貌成功。同行者趁客人离开房间进入其中，取走手令。掮客没有识破新外貌；下毒早于改貌。
7. 回到大堂时毒发，旧伤崩开。她将手令塞入桌底松动木条后，随后倒下。桌边主要血迹来自她。
8. 掮客发现手令失窃，结合房内动静、消失的金发住客和倒地者衣物，向老板索人；此时才可能推知改貌，不能倒置为识破后下毒。
9. 老板拒绝交人并拔剑阻拦，手部受伤，柜台旁留下少量血滴。掮客不愿将私下接人升级为公开杀人，负伤风险也无必要，因此暂退。无需表现为被彻底击败。
10. 老板将同行者安置在大堂便于照看。他知道她服过自己的药，却不知道客人具体下了什么毒，不敢乱用解药。天色将明、情况尚稳，他守着她，准备叫女主；女主先自行醒来。避免表现成老板明知急症却整夜擦剑不救人。
11. 开场擦剑：整理昨夜用过的兵器，剑与手上沾有扶人时的血；不据此直接认定剑刃伤了同行者。

药理只设两件事：改貌药改变外貌；客人的毒造成昏睡，原有伤势使症状加重。无需药物相克规则。解毒不会自动恢复金发，本版不制作两种外貌结局。

## 4. 三人的知识、隐瞒与诉求

| 人物 | 开场知道 | 尚不知道 | 想隐瞒 | 当前想得到 |
|---|---|---|---|---|
| 女主 | 护送约定、她的伤势、客栈由旧人推荐 | 下毒、改貌交易、取令行动、老板旧账 | 师门调查及自己也需要同行者协助 | 救人、安全离店、维持合作 |
| 同行者 | 服药、取令、藏匿位置、手令内容 | 自己何时中毒、倒下后的冲突 | 尚未充分信任女主，主动留了后手 | 拿回手令，保留去留决定权 |
| 老板 | 售药、倒地、拦人、自己的旧事 | 下毒具体品种、最初的偷令计划及藏处 | 曾参与强行送人、与掮客未断干净 | 两人脱险、承担有限责任、保住店 |

同行者的行动确实取得有用手令，不以“冒险失败，所以以后该听话”收束。女主不自动透露师门案。老板不能凭空知道手令藏处或客人下毒过程。

## 5. 探索布局与信息产出

核心调查组控制在八组，每组可含少量子热点。

| ID | 位置/物件 | 直接产出 | 可解锁内容 |
|---|---|---|---|
| E01 | 二楼己方床铺、行李与杯子 | 行李未带走；杯有药渍 | 主动下楼的推测；询问服药，药渍本身不能证明谁下毒 |
| E02 | 大堂同行者：呼吸、旧伤、外貌 | 尚稳但唤不醒；旧伤再开；外貌变化 | 救治任务；药笺核对；询问改貌 |
| E03 | 桌边血迹与桌底木条 | 血与旧伤对应；桌底可找到手令 | 取令行动、临行选择、相关质问 |
| E04 | 柜台血滴与老板手伤 | 存在第二名伤者 | 追问交手，修正单一袭击推测 |
| E05 | 昨夜客房：药粉包装、残余饮食 | 确认昏睡毒类型；客人有药物来源 | 取得正确解药；追问下毒先后 |
| E06 | 柜台药箱及随行药笺 | 区分改貌药和解药，确认用法 | 老板协助或女主自行救治 |
| E07 | 剑鞘镖号与旧账 | 老板曾护送活人且与客人有往来 | 旧事对话、追责取剑 |
| E08 | 老板、醒后同行者的对话 | 证词与动机 | 真相确认、合作变化、取剑与约定 |

手令不需要像素搜寻：桌边血迹终点、木条新划痕提供提示；醒后同行者可以直接告知。老板最多描述她倒下前摸过桌下，不能知道确切藏处。

客房可进入，无须新增钥匙谜题。旧账仅证明往来，不能单独证明历史受害者结局。药物包装只证明客人持毒，完整下毒归因还需其他证词或线索。

## 6. 核心流程与自由顺序

A. 二楼醒来，可查房或直接下楼。
B. 大堂自由调查同行者、血迹、老板；同时出现明确的救治目标。
C. 确认毒物，取得解药、重新包扎并唤醒。老板可以帮忙，也可由女主按药笺自行完成。药笺应明确由原照顾者提供，且列有该类常见毒物的应对，避免万能说明书。
D. 同行者醒来，调查不关闭；可继续客房、桌底、剑与旧账调查。
E. 经托付、追责或夺取获得剑。
F. 两人协商临行约定，一起越过出口，通关。

最短合法路径：检查伤者→询问老板→查客房毒物→从药箱取解药救醒→商谈取得剑→确认继续亲自护送→离店。可以不知道手令和老板旧事。

对话态度不锁死路线：求助让老板主动提供线索；盘问增加核对机会；威胁使他停止主动照护，但仍允许取用救治物品。不得因一次语气选择永久封死救人或所有取剑途径。

## 7. 行为差异必须发生在通关前

- 先救人：同行者先问客人去向，可能主动交代手令。
- 先找手令：女主可带证据询问；同行者先问女主如何理解接管命令。
- 错认老板害人：同行者醒来会主动承认自己要求改貌。
- 揭出旧账：老板从泛泛解释转为承认自己曾以履约为由忽视被送者意愿。
- 信任老板照护/独自救治：改变救治动作参与者及之后的称呼、主动信息。
- 拿走手令后是否归还/经同意代管：改变物件归属与同行者交代方式，不等同于自动加减好感。

建议记录具体行为，少用不可解释的总好感。例：是否征询同意、是否归还手令、是否公开指控、是否修正误判。单纯点击调查不应被当成冒犯；明确的翻查私人物品或夺物才有关系反应。

## 8. 剑的三条取得路径

S1 托付：救醒同行者，了解老板旧事，明确愿意尊重她的去留意愿；老板自愿交剑防身。
S2 追责：救醒同行者，掌握老板与掮客往来并通过对话确认昨夜经过，要求其为脱险承担代价；老板交剑，但不求被视作恩人。
S3 夺取：救醒同行者后可明确威逼取剑。老板因手伤与不愿再伤人而退让，无战斗。此路径应始终作为通关兜底，但必须有明确夺取确认与当场反应。

剑不承担开门钥匙功能。交剑后不因重开对话重复生成。老板失去剑后的自保风险在对白中承认，不强行以同一套感谢台词覆盖三条路径。

## 9. 结局数量：三种离店约定，九种主要收束组合

建议定义三个“约定结局”，不分好坏：

P1 亲自履约：女主承诺亲自送到，维持原约定；不需要手令信息。同行者可能接受可靠性，也可能仍担心自己缺少参与权。
P2 共同决定：继续回家，但遇到家中来人、路线改变或转交护送时，双方须先商量。需要知道她对转交的担忧，并在对话中达成。
P3 暂缓交付：仍一起离开客栈，但先核实手令签发和接应安排，再决定如何接近目的地。需要取得并读过手令，且同行者明确同意；不是取消护送或立即展开新场景。

结局主 ID = P1/P2/P3；剑的取得 ID = S1/S2/S3。3×3=9 种主要收束组合，设计上允许九种都可达。玩家可以先受赠再改变判断，也可夺剑后与同行者重订约定；取剑方式不自动决定对同行者的态度。

不制作九段完整过场：出口统一演出，依次播放“同行约定回应”“老板对取剑方式的回应”，再按关键知情状态补一句。顺序和优先级固定，避免所有变体叠加。额外的真相数量、手令归属、主动交代状态属于修饰，不宣称成几百个结局。

结算可显示：离店约定 + 剑的来由 + 已确认真相 X/8。不能只在结算展示差异，前述救治、交代、交物与对话必须先发生。

## 10. 真相统计：八个独立真相单元

“证据数量”与“确认真相数量”分开。每个真相有三个状态：未知、存疑、已确认。只有已确认计 1，同一事实多来源不重复计数；不按对话点击次数计分。

| ID | 真相单元 | 存疑来源 | 确认条件（本版建议） |
|---|---|---|---|
| T01 | 同行者主动离房并参与取令 | 行李未动、回程血迹 | 同行者明确承认取令行动；手令也可先找到但不自动知道动机 |
| T02 | 改貌是同行者知情请求、老板提供 | 杯子、外貌、老板说法 | 同行者承认请求及服药；或老板售药证词与同行者明确认可相互对应 |
| T03 | 客人提前下昏睡毒，改貌药不是昏迷主因 | 毒物包装、症状 | 毒物与残食相符，且服药/用餐时间经两人证词核对；救治成功仅确认毒物判断，不单独证明凶手 |
| T04 | 大堂主要血迹来自同行者旧伤 | 血迹位置、旧伤 | 检查伤口与桌边血迹，并由同行者或老板确认倒地经过 |
| T05 | 老板昨夜拒绝交人并与客人交手 | 手伤、柜台血滴 | 老板具体交手证词 + 手伤/现场痕迹；界面表述为“确认其曾拦人”，不扩大成证明他从未犹豫 |
| T06 | 手令确来自家中渠道，要求接管她 | 发现手令 | 读手令，同行者识别签押/暗记并解释接管内容；不据此确认家庭阴谋 |
| T07 | 她隐瞒行动是担心女主依据手令转交她 | 取令与隐瞒行为 | 她在对话中明确说明担忧。应保留可直接询问的路径，不依赖隐藏好感门槛 |
| T08 | 老板曾参与强行送人，后来放人因此与掮客结怨 | 镖号、旧账 | 查镖号/账目后追问，老板承认旧事；明确这是已核对部分记录的当事人陈述，不声称知道旧受害者最终命运 |

真相计数 = 已确认 T01—T08 的数量，范围 0—8。通关无最低数量门槛，实际最短流程可能自然确认其中若干项。UI 可显示“已确认 X/8”，不实时弹出刷分式加分；证词和证据在调查记录中分别呈现。

八个单元等权只为展示，不以百分比分配好坏评价。T07 是动机信息，T03 是事件归因，不应因后者证据物件更多而计更多分。全部确认仍不能知道家中阴谋、掮客幕后雇主、旧受害者下落或师门案真相。

确认触发应依据已收集信息随时重算：先读信后听证词、先听证词后读信结果相同。必须防止“错过一句话就永久无法确认”。已确认事实不因 NPC 后续敌意而消失；玩家的错误指控另记为判断，不污染作者真相。

## 11. 开发状态建议（逻辑规格，不是代码）

分开存五类状态：
1. 世界进度：同行者醒否、解药取得/使用、剑归属、门闩、是否已通关。
2. 证据与证词：按 ID 去重，记录已观察、已读取、已获得哪段证词；取得手令不等于已读。
3. 知识：T01—T08 的状态及支持来源；由证据/证词组合推导。
4. 行为与关系事实：救治由谁协助、曾否指控及修正、手令是否归还、是否征询；避免万能善恶分。
5. 收束：SwordOutcome、DeparturePact，以及少量临别对白修饰标记。

出口条件：同行者已醒且可随行 + 女主持剑 + 已达成有效离店约定 + 两人到达出口。原三个固定条件不变，“约定”在出口短对话中完成，不额外设置收集门槛。未满足时明确提示缺哪项，门本身可提前打开；提前跨门触发女主回望/停止，不能把同行者丢下通关。

约定和取剑结果应在明确确认时写入，可在离店前通过重谈修改约定；真正结算以跨出出口的最后有效状态为准。非重复消耗物、对白一次性标记、物件归属均须保存，存读档不能重复计真相或丢失剑。

## 12. 必要验收与制作优先级

先实现：最短救治路线、同行者醒前/醒后两阶段、手令取得与解释、三条取剑、三种离店约定、真相记录。再补态度差异、主动交代、旧事细节和动作表现。

设计验收：
- 先查客房/先救人/先找手令都能走通；后得到的证词可补确认。
- 不知老板旧事仍能取得剑离开；不知手令仍能用 P1 通关。
- 九种 P×S 组合都有合法路径；任何额外条件不得无意删掉组合。
- 威胁老板后仍可独自救治；错误指控后能修正态度。
- 取得、阅读、归还手令是不同状态，不会误触同行者已知情对白。
- 结算真相数与记录中确认项相同；重复调查、换来源、存读档不增数。
- 掮客只在改貌前认人下毒；老板不提前知道藏信位置；血迹来源前后一致。
- 不出现家中命令等于同行者同意、全真相等于最好结局的默认评价。
