# 客栈 Demo：建筑 v2 玩法整合

日期：2026-11-04。Unity 6000.0.60f1。

## 场景入口

使用 `游戏工作区/wuxia/Assets/Scenes/InnPlayable_v2.unity`，已设为 Build Settings 第一项。素材场景 `InnArtPreview_v2.unity` 和灰盒 `SampleScene.unity` 保留。新场景复制素材场景中的 Assembly；未改动原素材场景、FBX 或预制体资源。

人物、剧情道具、碰撞和交互仍在 Play 时生成。编辑态能看到建筑；进入 Play 才出现女主、同行者、老板和线索。`Inn Demo · Playable Building` 的 `buildingAssembly` 引用控制是否使用新建筑。原灰盒分支保留，自动启动检查限定在当前场景，避免另一个素材场景的禁用标记阻止游戏启动。

女主1.60m、同行者1.70m、老板1.75m。建筑网格添加静态非凸 MeshCollider，装饰磨损和旗幡除外；替代的灰盒墙、楼梯、房间、屋顶、家具停用，不产生双重阻挡。隐藏的原地面仅保留地面及门外落脚碰撞。

15个交互点全部重新安排到可站立位置附近。空床交互位于实际同行者床脚；药笺与杯在小几；柜台锚点放在台前；木条锚点对应实际餐桌，避免穿柜台调查。

## 剧情与存档

保持原顺序：叫床发现无人 → 下楼调查 → 客房辨毒 → 取解药、救醒包扎 → 取剑、商量约定（顺序可交换）→ 双人离店。快捷键不变。J手记、Q限时观察、E打开/关闭、键盘方向键镜头继续可用。

新布局版本5，灰盒版本4。读取不同布局版本的存档时保留剧情状态、重置人物到安全位置；剑未取得时恢复到当前布局柜台，而非旧坐标。没有覆盖用户的现有存档。

## 已验证

- 编译错误0。Unity图形后端出现过 memoryless depth load/store 警告，未出现脚本错误。
- 两名角色米制高度、柜台露出高度、床长、二楼净高4.15m检查通过。
- 96组房间/走廊/门口镜头避障采样通过。
- 15个交互点均通过：附近存在无实体重叠、无遮挡、且会被实际 Nearest 选择的站位采样。此项不是实际键盘逐项通关。
- CharacterController移动验证：出生房出门、走廊、昨夜客房、平台、下楼、正门，目标误差约0.08–0.12m。女主上楼也通过。
- 同行者CharacterController上楼、平台和走廊通过；跟至女主所在房间时被女主身体挡在约0.67m外，符合实体碰撞。
- 实际Play的离店阶段通过：测试状态下持剑、已约定、破门，两人跨门后 won=true。女主约(-.64,.03,-11.49)，同行者约(.46,.88,-10.71)。测试后重新启动，恢复无进度开局。
- 原剧情规则测试通过：9组合×两种约定/取剑顺序、最短路线、重复保护、8真相证据顺序、存档历史往返。

仍需人工Playtest完整键鼠体验、室内明暗舒适度、观察发现线索的难度、跟随者经过家具时的体感。没有宣称已人工从头到尾逐选项通关。
