# 《荒夜客栈》Demo · Figma UI 设计交接 v1

日期：2026-11-03。本文件可整份交给 Figma 设计对话。先完成 UI 设计与资产，不改写剧情，不新增玩法。当前 Unity 内已有功能占位排版，允许设计优化布局。

## 1. 产品与气质

第三人称女主武侠客栈解谜，小空间探索。夜尽天明、木质客栈、旧纸与墨迹、克制的悬疑。女主受托护送受伤同行者，清晨叫人时发现床空；楼下同行者昏迷、老板擦剑。最终救醒、持剑、确认约定，两人离店。

UI 方向：可读、安静、轻纸张与木纹质感，细线或印记作装饰。调查像旅途中随手记下的见闻。标题可有宋/明朝类气质，正文用清楚的中文字体。角色对话、女主心想、眼前观察、纸面文字要有视觉层级。避免战斗 HUD、血条、商城感、夸张金光和现代侦探电脑界面。

结算的一排“成就 icon”表现为八项往事徽记：已确认、待核对、未发现。它们表示玩家知道多少，不是善恶、好感或结局优劣。三种约定与三种取剑方式不能被配色暗示为好、中、坏。

## 2. 画布与交付方式

- 主设计稿：1920×1080，16:9。另检查 1280×720 的缩放可读性。
- 四边约 64px 安全区；探索 HUD 尽量轻，保留角色与场景观察空间。
- 组件使用 Auto Layout，长中文可换行。提供正文 2/4/6 行、选项 1/5/8 项的状态。
- 需要可编辑的 Figma 文件/帧链接，另导出每个关键界面的完整 PNG 预览。只有整张截图也可用于还原，但可编辑图层和尺寸标注更有利于后续接入。
- 动态文字、任务内容、按钮文案、数字、快捷键不烘焙进底图。
- UI 底板、装饰边框、图标分别导出透明 PNG；可拉伸面板标注九宫格边界。线条与小图标可另给 SVG 源文件；Unity 当前接入以 PNG 为先。
- 图片不是最终建模或场景概念设计；八张线索图本轮可先用统一比例的占位图，确认构图再替换正式插画。

## 4. 快捷键与关闭规则（保留）

WASD 移动；鼠标/方向键控制镜头；Shift 快走；E 打开交互，再按 E 关闭；关闭按钮和 Esc 都保留。J 打开/合上手记；Q 临时观察；Tab 收起/展开任务。F 在正门边撞门；F5 保存；F9 读取。通关后 R 重开，游戏中 Ctrl+R 重开。

已读选项：灰蓝文字，并有小型“已读”印记或符号；仍然可点。未读文字偏暖白，悬停提高对比。不能只靠颜色表达状态，也不能画成禁用按钮。未满足前置的剧情选项当前隐藏，不需要展示剧透的锁定选项。

## 5. J 手记的信息架构

- 顶部：行旅手记 / 客栈之夜，已确认 X/8，J/Esc 合上。
- 主区：八项图卡，可采用两列；超出区域滚动。卡片含小图片、主题、状态、小徽记。
- 详情区：选中项的大图、标题、状态、已经获得的物证/证词。没有取得的证据不能列成答案清单。
- 另有“随手记/物件”页：实际取得的信息与物件归属，留出长列表和滚动状态。
- 未发现：统一留白/轮廓图与“尚未发现的线索”，隐藏完整真相标题和插画。
- 待核对：显示中性主题和已知证据，图片使用中性占位/局部，不透出未确认情节。
- 已确认：完整标题、对应图片、明亮徽记。
- 不显示 T01 等内部 ID，不显示代码字段、条件表达式或“还差哪个按钮”的答案。

## 6. 结算布局

统一离店场景后显示：
1. 居中大字突出结局名称：“亲自履约 / 共同决定 / 暂缓交付”。“客栈之夜 · 离店结局”作为小字号引题。
2. 剑的来由为次级标题；本次约定的人物回应放在正文。
3. 老板对剑的来由的回应（托付/追责/夺取）。
4. 一行可选的手令归属、开门/破门修饰。
5. 八个徽记固定横排，每项有图像底片/缩略图，徽章叠在角上。选中时下方显示对应标题和图片/说明。
6. R 重开 / F9 读档。

“未发现”与“待核对”保留槽位，禁止自动展示未解锁的完整插画。设计部分解锁时仍然平衡，不让未满八个显得通关失败。不需要九张独立结局页。
